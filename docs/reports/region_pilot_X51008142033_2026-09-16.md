## Attribution

- Confirmed cause of page failure: **nine sequential extractor request
  timeouts** (45 s limit × 2 attempts each), same signature as the stored
  historical full-page failure (`Extractor failed: LLM request timed out`).
  Timeout source is the per-request HTTP boundary (`TimeoutError`,
  92.1 s/call), not the extractor stage limit (150 s, never hit per call)
  and not the overall deadline (1800 s; page took 856 s).
- What this does **not** establish (`unknown`, needs separate measurement):
  why each `qwen2.5:3b` CPU request exceeds 45 s (no token-progress signal
  exists — CPU level was never used as progress evidence); why
  `router_dispatches` recorded 0 on the Router path; settings in force at
  the original 2026-09-15 19:33 failure (unknown unless stored with the job —
  effective-today settings must not be back-projected).
- No code defect is confirmed beyond the measured behavior; no fix applied
  in this task. The 4 ambiguous splitter boundaries and the pre-flight
  budget shortfall (36 worst-case vs 24 cap) are recorded advisories, not
  causes of this failure.
